# Object Storage Service HTTP contract

Companion to [ARCHITECTURE.md](ARCHITECTURE.md) and [USAGE-GUIDE.md](USAGE-GUIDE.md). Source: current working tree on `master`, base commit `80b38457d75bdcaa92a1dcf63ad72bde673d8c70`, read 13 November 2026, including SDK/server changes in this task. This is a complete local consumer reference, not a request to edit an external API document.

**Runtime status:** the legacy object-route incompatibility is fixed using Express 5 named wildcards. Focused HTTP integration tests exercise the SDK through actual controllers/guards/middleware with in-memory metadata fixtures. Contracts otherwise derive from source; no live PostgreSQL or S3 integration was run. See the [SDK reference](../packages/sdk/README.md) for the typed client.

## Conventions

Base URL examples use `http://localhost:4000`, matching `.env.example`; without a PORT setting the app falls back to 3000. There is no `/api` prefix. Bucket paths use globally unique names, and object keys can contain `/`. Use simple ASCII keys in initial integrations; the controller and signer do not provide a full S3 URI-encoding specification.

Except key creation and Swagger resources, all listed application operations require either a valid `Authorization` signature or a verified `signature` query parameter. A policy granting principal `*` does not enable unsigned anonymous access. See [authentication](#authentication) and [presign](#generate-presigned-url). Signature checks produce an owner/access-key principal; normal authentication never creates `isRoot`.

All query values are strings, and empty flags such as `?versioning=` are detected by **presence**, not truthiness. If multiple recognized flags are present, the first branch in the documented dispatch order wins. Avoid combining subresources. Unknown flags normally fall through to the ordinary bucket/object operation; a POST with no recognized subresource fails with 403.

JSON control requests require a Content-Type containing `application/json`, with parser limit 10 MB. Object/part PUT requests retain their raw byte stream for all content types, including application/json; Content-Type is stored as object metadata instead of triggering JSON parsing. Non-JSON control bodies are not parsed. Class-validator decorators still do not execute because no ValidationPipe is configured; intended inputs below are not guaranteed validation failures for malformed data.

Successful JSON is returned **directly**: no `success`, `status`, or `entity` envelope. Default HTTP success status is 201 for POST and 200 for other implemented methods. DELETE returning void has an empty body at 200, not 204. Dates serialize as ISO timestamps. Undefined properties are omitted; `null` is an emitted value. PostgreSQL BIGINT sizes can be decimal strings on database-backed reads, whereas fresh stream-write responses return numeric sizes.

`x-request-id` is echoed/generated by an interceptor after guards run. Guard failures may have no ID header or error field. ETag headers contain the raw unquoted MD5 hex, not an S3 multipart ETag. No `If-Match`, `If-None-Match`, cache-condition handling, checksummed request-body header, or generic cursor/offset envelope is implemented.

## Shared wire shapes

The following notation defines complete emitted shapes for valid stored data. `?` means the property can be absent. No ellipses or undefined named types are required to interpret them. Nullable JSON columns can also hold malformed data accepted through unvalidated requests; the server does not normalize arbitrary stored values back into these intended types.

```typescript
type UUID = string;
type Timestamp = string;
type RuntimeSize = number | string;
type StringMap = Record<string, string>;
type StorageClass = 'STANDARD' | 'INFREQUENT_ACCESS' | 'ARCHIVE';
type VersioningStatus = 'DISABLED' | 'ENABLED' | 'SUSPENDED';
type EncryptionConfig = { algorithm: 'SSE_S3' | 'SSE_KMS'; kmsKeyId?: string };
type LifecycleRule = {
  id: string;
  prefix?: string;
  transitionAfterDays?: number;
  targetStorageClass?: 'INFREQUENT_ACCESS' | 'ARCHIVE';
  expireAfterDays?: number;
};
type CorsRule = {
  allowedOrigins: string[];
  allowedMethods: string[];
  allowedHeaders?: string[];
};
type BucketResource = {
  id: UUID;
  name: string;
  region: string;
  ownerId: string;
  versioningStatus: VersioningStatus;
  defaultEncryption: EncryptionConfig | null;
  lifecycleRules: LifecycleRule[] | null;
  corsConfig: CorsRule[] | null;
  replicationTarget: string | null;
  createdAt: Timestamp;
  updatedAt: Timestamp;
};
type PolicyStatement = {
  principal: string;
  action: string;
  resourcePattern?: string;
  effect: 'ALLOW' | 'DENY';
};
type PolicyRow = {
  id: UUID;
  bucketName: string;
  principal: string;
  action: string;
  resourcePattern: string;
  effect: 'ALLOW' | 'DENY';
  createdAt: Timestamp;
  updatedAt: Timestamp;
};
type ObjectMetadata = {
  key: string;
  size: RuntimeSize;
  etag: string;
  contentType: string;
  versionId: string;
  storageClass: StorageClass;
  lastModified: Timestamp;
  userMetadata: StringMap;
};
type PutResult = { key: string; etag: string; versionId: string; size: number };
type DeleteResult = { key: string; deleteMarker: boolean; versionId?: string };
type CopyResult = { etag: string; versionId: string; lastModified: Timestamp };
type ListObjectsResult = {
  bucket: string;
  prefix?: string;
  delimiter?: string;
  isTruncated: boolean;
  nextMarker?: string;
  contents: ObjectMetadata[];
  commonPrefixes: string[];
};
type VersionMetadata = ObjectMetadata & { isLatest: boolean; isDeleteMarker: boolean };
type ListVersionsResult = { bucket: string; versions: VersionMetadata[] };
type PartRow = {
  id: UUID;
  uploadRecordId: UUID;
  partNumber: number;
  etag: string;
  size: RuntimeSize;
  storagePointer: string;
  createdAt: Timestamp;
  updatedAt: Timestamp;
};
type ApiError = { error: { code: string; message: string; requestId?: string } };
```

Common path parameters: `bucket` is the bucket **name**, not its UUID; `key` is the full key including any slash segments. `versionId` is the public version string from writes/list versions, never the version row's internal PK. `uploadId` is the public multipart ID from initiation, never `uploadRecordId` from parts. Missing optional response associations are not emitted: bucket responses do not include `objects`, and part rows do not include an `upload` object.


## Authentication

Header form:

```text
Authorization: OSS-HMAC-SHA256 Credential=AKIA0123456789ABCDEF, SignedHeaders=host, Signature=<computed-hex>
```

Canonical payload = newline join of uppercase method, Express request path, sorted parsed `key=value` query strings joined by `&`, sorted signed `header:trimmed-value` entries joined by newline, and sorted signed-header names joined by semicolon. HMAC-SHA256 uses the per-access-key secret directly, returning hex. It has no body digest, timestamp, region derivation, or mandatory signature expiry. Query sorting here differs from the order-sensitive presigned URL signature. A [runnable client](USAGE-GUIDE.md#signed-request-client) is provided in the usage guide.

### Create access key

`POST /auth/keys` → **201**, no authentication. No path parameters or query fields. Required JSON body: `{ ownerId: string }`. `@IsString` is declared but not enforced. There is no existing-owner check or authorization of the requested owner ID.

Request:

```json
{ "ownerId": "demo-owner" }
```

Response is `{ accessKeyId: string, secretKey: string }`, with the plaintext secret returned only here:

```json
{ "accessKeyId": "AKIA0123456789ABCDEF", "secretKey": "synthetic-example-save-the-real-secret" }
```

The values above are synthetic, not usable credentials. No guaranteed field-validation error is implemented. Database/encryption errors can produce 500; global rate-limit errors also apply.

### Revoke access key

`DELETE /auth/keys/:accessKeyId` → **200**, empty body. Path `accessKeyId` is the public ID from key creation. No query/body. Requires valid authentication and same owner or root. Missing ID is a successful no-op. An already inactive key can be targeted using another active key; it cannot authenticate the request itself.

Example URL: `/auth/keys/AKIA0123456789ABCDEF`. Ownership error: `AccessDenied`, 403, `Cannot revoke an access key you do not own`. Authentication errors are shared. Presigned links do not consult this revoked status.

## Buckets

### List buckets

`GET /` → **200**. No path/query/body. Authentication required. Response is `BucketResource[]`, using the [full bucket shape/example](#reusable-complete-bucket-example), restricted to principal owner ID, with unspecified ordering and no pagination/count. Empty result:

```json
[]
```

Only shared authentication/rate-limit and unclassified persistence errors apply. Root does not change the owner filter.

### Create bucket

`PUT /:bucket` → **200**. Path: bucket name, 3–63 lowercase ASCII letters/digits/hyphens, first/last alphanumeric, no dots. No supported query fields in this mode. Required JSON body: `{ region: string }`, no implemented allowed-region list. Owner is taken from authentication; request `ownerId` is not used. Region's string validator is not executed; DB requires a non-null value.

```json
{ "region": "us-east-1" }
```

Response: complete `BucketResource`, as in the [baseline example](#reusable-complete-bucket-example). Existing bucket → `BucketAlreadyExists` 409, even for same owner; invalid name → `InvalidBucketName` 400. Concurrent create can surface an unmapped database error. Avoid reserved `/docs`, `/docs-json`, `/docs-yaml` names because those middleware paths shadow bucket access.

### Delete bucket

`DELETE /:bucket` → **200**, empty body. No query/body. Requires owner/root. All object rows must be gone, including hidden objects with marker/history; otherwise `BucketNotEmpty` 409. Missing bucket → `NoSuchBucket` 404. Owner failure → generic `FORBIDDEN` 403. The API does not provide recursive bucket deletion; multipart sessions/configurations are not explicitly purged by this operation, and their persistence can affect DB deletion behavior.

### Replace bucket policy

`PUT /:bucket?policy=` → **200**. Path bucket name; query `policy` flag only; owner/root required. Body is `{ statements: PolicyStatement[] }`, every statement field defined in [shared shapes](#shared-wire-shapes). `principal` is `*` or exact owner ID, `action` is `*` or exact action string, effect is ALLOW/DENY. Missing/null resource pattern defaults to `bucket/*`; `*` in resource pattern is a wildcard. Entire statement set is replaced. Empty array clears. Omission/null of statements is not a supported clear operation.

```json
{
  "statements": [
    {
      "principal": "reader-owner",
      "action": "GetObject",
      "resourcePattern": "demo-assets/public/*",
      "effect": "ALLOW"
    }
  ]
}
```

Response:

```json
{}
```

Consumer-visible actions used by object controllers are `PutObject`, `GetObject`, `DeleteObject`, `GetObjectTagging`, and `PutObjectTagging`. No `s3:` prefix matching. Matching DENY overrides matching ALLOW for nonowners; owners/root bypass statements entirely. Relevant errors: NoSuchBucket, owner FORBIDDEN, shared errors. Replacement is not an atomic promise to preserve old rules if it fails.

### Read bucket policy

`GET /:bucket?policy=` → **200**. Query `policy` flag; no body. Owner/root required. Response is full `PolicyRow[]`, **not** `{ statements: [...] }`. No policy → `[]`.

```json
[
  {
    "id": "22222222-2222-4222-8222-222222222222",
    "bucketName": "demo-assets",
    "principal": "reader-owner",
    "action": "GetObject",
    "resourcePattern": "demo-assets/public/*",
    "effect": "ALLOW",
    "createdAt": "2026-11-13T06:01:00.000Z",
    "updatedAt": "2026-11-13T06:01:00.000Z"
  }
]
```

Errors: NoSuchBucket, owner FORBIDDEN, shared errors. No sorting or statement grouping is promised.

### Set versioning

`PUT /:bucket?versioning=` → **200**. Query `versioning` flag, no other supported fields. Owner/root required. Body `{ status: 'ENABLED' | 'SUSPENDED' }`; declared enum validator is not enforced by a pipe. This API's intended setter does not offer DISABLED after creation.

```json
{ "status": "ENABLED" }
```

Response: full `BucketResource` from the [baseline example](#reusable-complete-bucket-example), with `versioningStatus` changed to ENABLED and updated timestamp. Writes retain versions in **all** statuses; ENABLED changes bare DELETE to inserting a marker. SUSPENDED bare DELETE removes version rows. Errors: NoSuchBucket, owner FORBIDDEN, DB enum/error failures, shared errors. Omitted status is not an intentional reset/default operation.

### Read versioning

`GET /:bucket?versioning=` → **200**. Query flag, no body; any authenticated principal. Response `{ status: VersioningStatus }`:

```json
{ "status": "DISABLED" }
```

No owner or policy check. Error: NoSuchBucket plus shared errors.

### Replace lifecycle rules

`PUT /:bucket?lifecycle=` → **200**. Owner/root, query flag. Body is a **bare array** of `LifecycleRule`, not `{ rules }`. Fields: required intended string ID; optional string prefix; optional numeric transition/expiry days; optional target class INFREQUENT_ACCESS/ARCHIVE. No nested runtime validation or nonnegative/integer checks. A useful transition needs both threshold and target; expiry and transition can coexist, expiry wins when both eligible.

```json
[
  {
    "id": "public-retention",
    "prefix": "public/",
    "transitionAfterDays": 30,
    "targetStorageClass": "INFREQUENT_ACCESS",
    "expireAfterDays": 365
  }
]
```

Response: full `BucketResource`, using the [baseline](#reusable-complete-bucket-example) with `lifecycleRules` replaced by this array. `[]` clears effective rules. Rules run in the deployment process timezone daily at 02:00, consider latest non-marker versions only, and age uses fractional elapsed days. Transition is a metadata label, not physical archive movement. Expiration with retained history currently leaves a stale latest pointer; see [architecture](ARCHITECTURE.md#lifecycle). Errors: NoSuchBucket, owner FORBIDDEN, shared errors. Omission is not a patch/merge instruction.

### Read lifecycle rules

`GET /:bucket?lifecycle=` → **200**. Query flag, no body; any authenticated principal. Response `{ rules: LifecycleRule[] }`, with no configured rules normalized to empty array:

```json
{ "rules": [] }
```

Error: NoSuchBucket plus shared errors. No pagination or per-rule enabled/status flags.

### Set default encryption

`PUT /:bucket?encryption=` → **200**. Owner/root; query flag. Body `EncryptionConfig`, algorithm SSE_S3/SSE_KMS, optional string `kmsKeyId`:

```json
{ "algorithm": "SSE_S3" }
```

Response: full `BucketResource`, [baseline](#reusable-complete-bucket-example) with `defaultEncryption` set to the config and timestamp updated. Replaces configuration for future ordinary PUTs, not existing versions. SSE_KMS is a local envelope-encryption simulation; no external KMS call/key selection uses `kmsKeyId`. Multipart completion bypasses encryption. No dedicated disable endpoint is defined; malformed or null inputs are not validated/normalized into a stable public reset contract. Errors: NoSuchBucket, owner FORBIDDEN, shared errors.

### Read default encryption

`GET /:bucket?encryption=` → **200**. Query flag, no body; any authenticated principal. Response is `EncryptionConfig` or `{}` when no truthy stored config:

```json
{}
```

Configured response example:

```json
{ "algorithm": "SSE_KMS", "kmsKeyId": "demo-key-label" }
```

Error: NoSuchBucket plus shared errors.

### Replace stored CORS rules

`PUT /:bucket?cors=` → **200**. Owner/root; query flag. Body is bare `CorsRule[]`: `allowedOrigins` string array, `allowedMethods` string array, optional `allowedHeaders` string array. No per-rule max-age/exposed-header field is implemented or validated.

```json
[
  {
    "allowedOrigins": ["http://localhost:5173"],
    "allowedMethods": ["GET", "PUT", "HEAD"],
    "allowedHeaders": ["authorization", "content-type"]
  }
]
```

Response: full `BucketResource`, [baseline](#reusable-complete-bucket-example) with `corsConfig` replaced by supplied rules. `[]` clears stored rules; omission is not a merge. Rules are **stored only** and do not override globally enabled Express CORS. Errors: NoSuchBucket, owner FORBIDDEN, shared errors.

### Read stored CORS rules

`GET /:bucket?cors=` → **200**. Query flag, no body; any authenticated principal. Response `{ rules: CorsRule[] }`, default empty:

```json
{ "rules": [] }
```

Error: NoSuchBucket plus shared errors.

## Object listings

### List objects

`GET /:bucket` → **200**. No body; any authenticated principal, with no owner or ListBucket-policy evaluation.

| Query       | Type/default                            | Actual semantics                                                                                                                               |
| ----------- | --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `prefix`    | Optional string                         | Key prefix filter; SQL `%`/`_` wildcard escaping is absent. Echoed when supplied.                                                              |
| `delimiter` | Optional string                         | Group matching key suffixes into unique commonPrefixes; no restriction to `/`. Grouping occurs after raw-page selection. Echoed when supplied. |
| `marker`    | Optional string                         | Exclusive key bound, lexicographic `key > marker`, alongside prefix. Not returned as an echo.                                                  |
| `maxKeys`   | Intended optional number, fallback 1000 | No cap/conversion. HTTP strings cause string concatenation in lookahead limit; custom values can fail. Omit for reliable default behavior.     |

Example URL: `/demo-assets?prefix=public%2F&delimiter=%2F`. No array/boolean/date/offset query fields. Unknown fields ignored unless they select another bucket subresource. For `maxKeys=2`, string concatenation makes the lookahead fetch limit `'21'`, while response slicing/comparison separately coerce `'2'`. Numeric strings therefore inflate fetching; malformed values may fail. Live database pagination was not exercised.

Response is full `ListObjectsResult`; no total count. Missing optional query echoes and nontruncated `nextMarker` are omitted. Metadata has no tags/pointers/encryption references. Empty bucket has `contents: []`, `commonPrefixes: []`, `isTruncated: false`.

```json
{
  "bucket": "demo-assets",
  "prefix": "public/",
  "delimiter": "/",
  "isTruncated": false,
  "contents": [
    {
      "key": "public/hello.txt",
      "size": "5",
      "etag": "5d41402abc4b2a76b9719d911017c592",
      "contentType": "text/plain",
      "versionId": "33333333-3333-4333-8333-333333333333",
      "storageClass": "STANDARD",
      "lastModified": "2026-11-13T06:02:00.000Z",
      "userMetadata": { "project": "demo" }
    }
  ],
  "commonPrefixes": ["public/images/"]
}
```

When truncated, resubmit returned `nextMarker` with the same filter. Hidden marker parents are excluded. Error: NoSuchBucket, possible 500 for invalid limit or persistence failures, shared errors. There is no guaranteed DTO-validation 400 for query mistakes.

Any authenticated principal; no owner/policy check. `marker`, `maxKeys`, `delimiter`, and `versionId` have no filtering effect in this mode. No pagination/count. Response `ListVersionsResult`; objects ordered key ascending, each object's versions creation-time descending, without stable timestamp tie breaker. Includes delete markers and hidden parents. `isLatest` compares internal PKs, but emitted versionId is public.

```json
      "isDeleteMarker": true

      "size": "5",
```

## Object reads and writes

All operations here take bucket name and full object key path parameters. Authorization checks bucket ownership/root or matching policies for the indicated action. Shared failures: missing bucket, generic policy FORBIDDEN, signature/rate-limit errors, and unclassified storage/database/crypto errors.

### Upload object

`PUT /:bucket/:key` → **200**, action `PutObject`. No supported query fields in ordinary mode. Body is raw bytes; Content-Type optional (stored default octet-stream), `x-amz-meta-NAME` headers optional (stored metadata keys are prefix-stripped, generally lowercased by HTTP). JSON Content-Type is supported and does not consume the object PUT stream in middleware.

Example: `PUT /demo-assets/public/hello.txt`, `Content-Type: text/plain`, `x-amz-meta-project: demo`, raw body `hello`.

Response `PutResult`:

```json
{
  "key": "public/hello.txt",
  "etag": "5d41402abc4b2a76b9719d911017c592",
  "versionId": "33333333-3333-4333-8333-333333333333",
  "size": 5
}
```

Every write returns a new public version ID and retains prior versions regardless of versioning status. No replay/idempotency key, overwrite precondition, size quota, or request checksum validation. Bucket default encryption applies to this operation. No dedicated per-request SSE header is used.

### Copy object

`PUT /:bucket/:key` with `x-amz-copy-source: /source-bucket/path/to/key` → **200**. Destination action PutObject and source action GetObject. Body unused; no source-version/query option; source path parsing is literal, not URL-decoded by copy helper. UploadId+partNumber dispatch takes priority if both present.

Response `CopyResult`:

```json
{
  "etag": "5d41402abc4b2a76b9719d911017c592",
  "versionId": "55555555-5555-4555-8555-555555555555",
  "lastModified": "2026-11-13T06:04:00.000Z"
}
```

Copies content type/user metadata, omits tags, creates a new destination version. Source missing/marker → NoSuchKey 404. Encrypted sources are read as stored ciphertext in this copy implementation; use download-and-upload for a plaintext-preserving encrypted copy.

### Download object

`GET /:bucket/:key` → **200**, or **206** whenever a range is parsed; action GetObject. No body. Query `versionId?: string` selects a public historical version, otherwise latest. A marker or missing version returns NoSuchKey; a historical non-marker can be read when latest is a marker.

Optional `Range: bytes=START-END` or `bytes=START-`; inclusive numeric endpoints. Suffix ranges are ignored, malformed forms usually ignored, multi-range is not implemented, and regex matching is not anchored. There is no guaranteed 416 validation. On encrypted objects range is ignored in the service but status can still be 206. Out-of-bounds behavior depends on adapter and is not normalized.

Response body is **raw bytes**. Application sets Content-Type, ETag (MD5), x-amz-version-id. It does not explicitly set Content-Length, Content-Range, Last-Modified, user-metadata headers, or Accept-Ranges. Example body for the above write is `hello`. Error response before streaming uses `ApiError`; failures after streaming starts have no guaranteed JSON error shape.

### Read object headers

`HEAD /:bucket/:key` → **200**, no body, action GetObject. Same path and optional `versionId` as download, no supported request body/range behavior. Express uses the GET handler, which explicitly detects HEAD after subresource dispatch.

Application-set response headers for the `hello` example:

```text
Content-Length: 5
Content-Type: text/plain
ETag: 5d41402abc4b2a76b9719d911017c592
x-amz-version-id: 33333333-3333-4333-8333-333333333333
```

It returns no user metadata headers. NoSuchKey/missing bucket/policy/shared errors apply; HTTP suppresses error bodies for HEAD. HEAD with uploadId/presign/tagging follows that subresource branch instead and does not perform the ordinary metadata branch. Root/bucket HEAD also inherit Express GET behavior but have no dedicated product contract or explicit object metadata headers.

### Delete object or version

`DELETE /:bucket/:key` → **200**, action DeleteObject. No body. Optional string query `versionId` means permanently remove that public version (including markers); absent means delete latest according to bucket status. Unknown keys are **404**, not S3-style success.

ENABLED without version ID: `DeleteResult` with marker ID:

```json
{
  "key": "public/hello.txt",
  "deleteMarker": true,
  "versionId": "44444444-4444-4444-8444-444444444444"
}
```

Specific version removal, including removing a marker:

```json
{
  "key": "public/hello.txt",
  "deleteMarker": false,
  "versionId": "44444444-4444-4444-8444-444444444444"
}
```

DISABLED/SUSPENDED without version ID:

```json
{ "key": "public/hello.txt", "deleteMarker": false }
```

Explicit removal recalculates latest from remaining creation timestamps. Removing latest marker can expose an older version. Hard delete removes all version rows but only latest payload bytes, leaving possible orphaned historical bytes. NoSuchKey covers missing object or requested version; other shared errors apply.

### Read object tags

`GET /:bucket/:key?tagging=` → **200**, action GetObjectTagging. Query flag, no body. `versionId` is ignored; always latest non-marker. Response `{ tags: StringMap }`, default `{ tags: {} }`:

```json
{ "tags": { "team": "demo", "retention": "standard" } }
```

NoSuchKey and shared errors apply. Metadata header values and tags are separate stores.

### Replace object tags

`POST /:bucket/:key?tagging=` → **201**, action PutObjectTagging. Query flag, required intended JSON body `{ tags: StringMap }`. No enforced tag-count, length, key-name, or nested DTO limits. Whole map replacement; empty map clears. Omission/null is not a defined merge/clear instruction. `versionId` ignored.

```json
{ "tags": { "team": "demo", "retention": "standard" } }
```

Response:

```json
{}
```

NoSuchKey and shared errors apply.

### Generate presigned URL

`GET /:bucket/:key?presign=GET&expiresIn=3600` → **200**. Generation checks GetObject for GET links and PutObject for PUT links. No body. Query presign accepts GET/PUT (empty defaults GET); unsupported method values produce BAD_REQUEST 400 when generation is reached. expiresIn is a numeric string, controller uses `Number(value) || 3600`; zero/NaN defaults 3600 and server negative/fractional/large lifetimes remain unbounded. versionId has no generation effect. Object existence is not checked, so links can target a new key if authorization allows it.

Response `{ url: string }` is a relative path. This complete synthetic response uses illustrative secret `synthetic-presign-secret` and expiry 13 November 2026 at 07:00 UTC. It is not a usable link for your instance; use the runtime-returned value:

```json
{
  "url": "/demo-assets/public/hello.txt?method=GET&expires=1794553200&ownerId=demo-owner&accessKeyId=AKIA0123456789ABCDEF&signature=9ba175a7091e07eaf2dc03beb239060e9b6ac81845546e8c692b2835cfaaa471"
}
```

On use, preserve exact returned query order/values, prepend server origin, and omit Authorization. The server encodes bucket/key path segments. HMAC verification requires the actual HTTP method to equal the signed GET/PUT value; a GET link does not permit HEAD. Wrong method, expiry, or mismatched signatures produce SignatureDoesNotMatch 401. Verification still does not check active access-key status. Current policy evaluation applies. Do not reorder parameters or append versionId/subresources. The SDK returns the same link with its configured origin prepended.

## Multipart uploads

Common path: bucket name/full object key; all branches require action **PutObject**, even part listing and abort. Each uploadId must be the public ID returned by initiation. Always keep the same bucket/key for its lifetime. The implementation does not bind upload lookup to the authorized URL resource; treat returned IDs as sensitive. There is no list-all-uploads route, per-upload owner field, automatic expiry, or completion replay key.

### Initiate multipart upload

`POST /:bucket/:key?uploads=` → **201**. Query `uploads` flag; no body. Optional Content-Type header is captured as the final object's content type; absent → final default octet-stream. Sending application/json merely as a content-type selector is subject to the JSON middleware; octet-stream is the straightforward binary workflow.

Response `{ uploadId: string }`:

```json
{ "uploadId": "66666666-6666-4666-8666-666666666666" }
```

No final object exists until completion. Missing bucket/policy/shared errors apply.

### Upload multipart part

`PUT /:bucket/:key?uploadId=ID&partNumber=N` → **200**. Both query strings required for this branch. `partNumber` is converted with Number, but no integer/positive/upper-bound validation exists. Body raw bytes, including when Content-Type is application/json. Every non-final submitted completion part must be at least 5 MiB, but this check occurs **at completion**, not upload.

Response `{ etag: string, size: number }`; for a single last part containing `hello`:

```json
{ "etag": "5d41402abc4b2a76b9719d911017c592", "size": 5 }
```

Keep etag exactly as returned. Sequential replacement of an existing part number stages a fresh pointer, saves new etag/size/pointer, then removes old bytes. A failed write/metadata save attempts candidate cleanup without intentionally deleting the old blob; an old-blob cleanup failure may be reported after replacement has saved. Concurrent replacement is not serialized, and completion/abort do not have replay guarantees. The SDK performs no automatic mutation retries. Missing upload → NoSuchUpload 404; shared errors apply. No standard S3 UploadPart size/quota contract is implemented.

### List multipart parts

`GET /:bucket/:key?uploadId=ID` → **200**. Query uploadId only, no body. Response `{ parts: PartRow[] }`, ascending partNumber, no pagination/count. Empty session → `{ parts: [] }`. It exposes full row fields rather than only `PartInfoDto`:

```json
{
  "parts": [
    {
      "id": "77777777-7777-4777-8777-777777777777",
      "uploadRecordId": "88888888-8888-4888-8888-888888888888",
      "partNumber": 1,
      "etag": "5d41402abc4b2a76b9719d911017c592",
      "size": "5",
      "storagePointer": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
      "createdAt": "2026-11-13T06:05:00.000Z",
      "updatedAt": "2026-11-13T06:05:00.000Z"
    }
  ]
}
```

Missing upload → NoSuchUpload; shared errors apply. Do not substitute uploadRecordId for uploadId in requests.

### Complete multipart upload

`POST /:bucket/:key?uploadId=ID` → **201**. Query uploadId, required intended JSON body `{ parts: { partNumber: number, etag: string }[] }`. Omission/null is not a no-op. Submit each stored part once in ascending number order; server count-checks and matches numbers/etags but does not enforce uniqueness/order. All entries except last need at least 5 MiB. Concatenation follows submitted order, not stored sort. The intended safe request for one last `hello` part is:

```json
{ "parts": [{ "partNumber": 1, "etag": "5d41402abc4b2a76b9719d911017c592" }] }
```

Response `PutResult`:

```json
{
  "key": "public/hello.txt",
  "etag": "5d41402abc4b2a76b9719d911017c592",
  "versionId": "99999999-9999-4999-8999-999999999999",
  "size": 5
}
```

Final etag is MD5 of all concatenated bytes. Bucket default encryption is bypassed. Session/part rows are removed on completed cleanup; repeating afterwards gives NoSuchUpload 404, not replayed 201/200. Failure during cleanup can occur after the object was created, so inspect object/version state before retrying. Errors: NoSuchUpload, NoSuchBucket on stored-bucket resolution, InvalidPart messages below, and shared errors. There is no explicit nonempty-parts guard.

### Abort multipart upload

`DELETE /:bucket/:key?uploadId=ID` → **200**, `{}`. Query uploadId, no body. Deletes known part data/rows and the upload session, without producing an object. Missing/already completed/already aborted → NoSuchUpload 404, not a successful no-op. Response:

```json
{}
```

Shared errors apply; partial cleanup is not rolled back.

## Swagger resources

`GET /docs` serves Swagger UI HTML, `GET /docs-json` serves generated OpenAPI JSON, and `GET /docs-yaml` serves generated YAML, normally **200**. No application signature requirement, path/query/body parameters, or success envelope is applied to these middleware resources. Their output is generated by Swagger, not a domain DTO. A UI redirect or trailing-slash normalization may occur through Swagger middleware. The document title is `Object Storage Service`, version `0.1.0`, with an `Authorization` apiKey scheme named `signature`.

A static signed header entered in Swagger may cease to work when method/path/query changes. Swagger does not generate HMACs or document every overloaded route/body/response. Use the companion and signed client for complete behavior. There is no explicit health, readiness, notification-configuration, replication-configuration, lifecycle-run, audit-query, or access-key-list route.
